# QuantQuest

A free, static, mobile-first quant interview practice PWA. No login, API, backend, or paid database.

## Quick start

Requires Node.js 20.9+ (Node 22 recommended).

```bash
npm install
npm run validate
npm test
npm run dev
```

Open http://localhost:3000. To verify the production build: `npm run build` then `npx serve out` (or `npm run start` is **not** supported with static export; use a static server).

## Deploy free on Vercel

1. Create a GitHub repository and push this folder: `git init`, `git add .`, `git commit -m "Initial QuantQuest"`, `git branch -M main`, `git remote add origin https://github.com/YOUR_USERNAME/quantquest.git`, `git push -u origin main`.
2. In Vercel choose **Add New → Project**, import the repository, choose Next.js, keep default build settings, and deploy on the Hobby plan. No environment variables required.
3. The `next build` command produces a static `out/` folder. Vercel detects Next.js automatically.

## iPhone offline install

Open the deployed HTTPS URL in Safari, wait until the page fully loads, then Share → Add to Home Screen → Add. Launch the installed icon while online once and wait for assets to cache. Then enable Airplane Mode and reopen the app; quizzes and solutions should work. Check Settings → Safari → Advanced → Website Data if troubleshooting, but **do not clear website data** unless you have exported a backup: it may delete progress. iOS can evict storage under pressure, so export JSON backups regularly. Safari private mode is not suitable for persistence.

## Questions

See [ADDING_QUESTIONS.md](ADDING_QUESTIONS.md) for a GitHub-only workflow and [templates/question-template.json](templates/question-template.json) for a complete example. Edit `data/*.json` directly. Each entry follows this example:

```json
{
 "id":"01-011", "category":"Probability", "subtopic":"Dice", "difficulty":"beginner",
 "text":"What is 1 + 1?", "inputType":"numeric", "answer":"2",
 "hint":"Add the integers.", "explanation":"One plus one equals two.",
 "estimatedSeconds":30, "tags":["arithmetic"]
}
```

For multiple choice use `"inputType":"multiple-choice"`, include `"options":["A","B","C"]`, and set `"answer"` to the exact matching option. Use unique IDs. Math can be written in `$...$` or `\(...\)` syntax. Run `npm run validate` and `npm test` after editing. The question files are bundled into the static app, so adding questions requires redeployment. The selection engine scales linearly/sort-based for 1,000+ questions.

## Learning rules

Daily challenges are selected once per local calendar day and saved in IndexedDB. Unseen questions have high priority; missed and due questions get boosts; mastered questions have low priority. Yesterday's questions are penalized. A small bank produces fewer than requested rather than duplicates. Review intervals after consecutive correct answers: 1, 3, 7, 14, 30, 60 days. A wrong answer resets consecutive successes and schedules tomorrow. Three consecutive correct reviews mark mastered. Every submitted answer is recorded; total solved is attempt count, including retries.

## Privacy and limitations

All progress lives in device IndexedDB; no synchronization between devices. Export/import is a full replacement, not a merge. Browser/site-data clearing or storage eviction can erase progress. Questions are static and never generated by an AI API. The bank is educational, not affiliated with any trading firm. Numerical answers use a 1e-6 relative tolerance (minimum 1e-8). Date and streak use the device's local clock.
